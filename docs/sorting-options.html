Three ways to let people organise the table. All three use your real entries. Worth separating two different needs as you look: sorting changes the order, grouping puts rows under headings, and filtering (which the table already does) hides rows. They solve different problems and can coexist.
Option 1

"Organise by" — groups the rows under headings

Closest to what you described. Choosing a theme regroups the whole table, newest first within each heading. Default stays "Date".

Things to weigh up

Sorting and filtering solve different problems. Filtering answers "show me the dementia work". Sorting answers "show me everything, arranged sensibly". Right now the table can only filter, and only if you spot a value in a row and click it.

Grouping (Option 1) suits a list this size. With 13 entries, grouping by theme shows the whole collection at a glance — four or five headings, two or three rows each. That reads like a portfolio. It gets unwieldy past about fifty entries, when the headings scroll off and you'd want filtering instead.

Sortable headers (Option 2) are the cheapest to add and the most familiar, but sorting alphabetically by theme is a strange thing to want. It mostly helps for Title and Published, and Published is already the default order.

Dropdowns (Option 3) fix a real discoverability gap. Nobody can filter by "White paper" unless an entry on screen happens to be one. A dropdown lists every option whether or not it's visible. The cost is three controls above the table on every visit, on a page you've been working to shorten.

"Past and present work" isn't in the data. Nothing records whether a project is ongoing or finished. There's an optional "if the work spans a period" field, but it's free text and mostly empty. If that grouping matters, it needs a new question on the form — worth deciding before building anything, since it changes what the control offers.

If you want a recommendation: Option 1, with the dropdown defaulting to "Date published" so the page looks as it does now until someone chooses otherwise. It matches what you described, suits the size of the collection, and adds one control rather than three. Option 3 is the better answer later, once there are enough entries that people need to narrow rather than browse.
